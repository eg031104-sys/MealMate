# Australian supermarket data investigation — 23 October 2026

## Actual integration status

**No live retailer product, price, specials, availability or retailer store-directory feed is connected.** A subsequent store-finder patch adds community OpenStreetMap location lookup via Photon and Private.coffee Overpass; see [source terms, behaviour and limitations](store-finder.md). V3 runs in explicit manual-store-catalogue mode for Coles, Woolworths, ALDI and IGA. The source selection is deliberately not described as live integration. No retailer accounts, private credentials, reverse-engineered checkout endpoints, anti-bot workarounds or scraper services were used.

Research found consumer-facing information and potential partner/open-data routes, but did not establish a documented, authorised, tested feed with reliable Australian store coverage for this application. This is not a claim that no commercial partner API exists.

## Implemented data contract

`SupermarketProvider` supplies store search and per-store product records. Each product can carry an external/internal identifier, ingredient key, exact compatible unit and package size, price, source URL/provider, observed timestamp, verification expiry, availability observation/source and optional special expiry/regular price. Future authorised adapters must use a server-side credential boundary; no API key field exists in the UI.

`manualProvider` is the only configured provider. It does not invent stores or return mock products. Users search their own saved locations by suburb/postcode or use an official locator, then enter the exact branch. Product notes are stored separately for each branch. Multiple products may supply the same ingredient; selection compares whole-package purchase cost and avoids a current unavailable observation when an alternative exists. V2 unscoped manual prices remain stored and can be explicitly copied to a chosen branch after user confirmation.

## Price and stock labels

- **Confirmed current price:** reserved for a connected trusted provider, a dated observation no more than 24 hours old and an unexpired verification deadline. No production provider currently qualifies.
- **Recently retrieved price:** trusted-provider observation within seven days without a current confirmation window. No such feed is currently configured.
- **User-entered price:** manual notes remain manual, including after browser/IndexedDB caching. An observation date is shown where known.
- **Estimated / demonstration price:** explicit provenance; never promoted to current price. The legacy V2 demo table is retained for backwards compatibility/tests but is not used as a selected V3 branch's catalogue.
- **Unknown / unverified imported price:** excluded from known purchase cost; makes the estimate partial. A forged/imported provider name cannot turn itself into a connected feed.

Availability is separate from price. User observations are labelled **User-reported**, never verified. Observations older than 24 hours become unknown. Trusted-provider verification is not available in this release. Unknown availability is not a claim of stock. Genuine-special badges require trusted, current provider evidence and valid offer dates; none are claimed in manual mode.

These 24-hour/seven-day policies are MealMate freshness policies, not retailer refresh promises. Manual data refreshes only when users save observations. Future adapter refresh intervals, authentication, legal reuse and rate limits must be agreed with the provider before enabling it.

## Planning and comparison limits

The generator evaluates the combined basket and package rounding with existing purchases, stock, portions and locked meals. It favours price coverage, affordable packages and ingredient reuse, excludes current unavailable observations, and preserves existing meals when no eligible replacement exists. It is a best-effort heuristic, not a guaranteed globally optimal weekly plan. Unknown prices cannot prove compliance with a budget. Existing/locked meals may already exceed the budget; cost-reducing replacements are allowed and overruns remain visible.

Store comparisons price the remaining basket at each selected branch while retaining actual spending. Partial coverage is labelled. Per-item store assignments change the budget catalogue for that item. No travel cost is guessed and the app does not automatically recommend multi-store shopping as cheaper.
